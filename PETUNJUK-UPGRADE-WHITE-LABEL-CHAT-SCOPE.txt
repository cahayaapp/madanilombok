CAHAYA APP — PETUNJUK UPGRADE WHITE-LABEL, CHAT, BANDWIDTH, DAN RUANG KONTROL
Versi: 2026.08 White-Label v1

A. SEBELUM MENGGANTI KODE
1. Simpan backup folder/repository aplikasi lama.
2. Simpan Export JSON Realtime Database di minimal dua tempat.
3. Jangan mengimpor ulang JSON; backup hanya untuk keadaan darurat.
4. Pastikan perubahan GitHub sebelumnya sudah di-commit.

B. PEMASANGAN
1. Ekstrak paket aplikasi terintegrasi.
2. Salin isi folder cahayaapp-main ke repository aktif.
3. Pilih Replace/Ganti untuk file yang sama.
4. Hapus file lama berikut bila masih ada:
   js/absensi-guru-config-JAM-BELAJAR-FIX.js
5. Commit dan Push melalui GitHub Desktop.
6. Tunggu deployment GitHub Pages selesai.
7. Buka cahayaapp.com melalui Chrome dan lakukan hard refresh.
8. Pengguna PWA yang masih melihat versi lama dapat menutup aplikasi, membuka ulang, atau menginstal ulang pintasan.

C. PERBAIKAN CHAT
1. Mesin chat pengurus kini hanya memakai js/pengurus-whatsapp-chat.js.
2. Portal Wali memakai satu mesin chat pada wali/dashboard/index.html.
3. Pesan, metadata room, dan inbox ditulis secara atomik agar pesan tidak hilang setelah dikirim.
4. Broadcast dibuat sebagai salinan pesan pribadi untuk setiap penerima.
5. Area ketik chat wali dibuat fullscreen di HP dan tidak ditutup menu navigasi bawah.
6. Bila percakapan lama tidak muncul di daftar, buka:
   Admin/Sistem -> Perbaikan Chat -> Bangun Ulang Inbox.
7. Jalankan Bangun Ulang Inbox satu kali saja. Proses ini tidak menghapus pesan.
8. Gunakan menu Pulihkan dari Backup JSON hanya bila record pesan benar-benar hilang dari Firebase.

D. SIDEBAR MULTI-PERAN
1. Menu akun yang memiliki beberapa peran otomatis dikelompokkan berdasarkan peran.
2. Grup dapat dibuka/tutup agar sidebar tidak panjang dan bercampur.
3. Modul yang dinonaktifkan melalui konfigurasi white-label tidak akan ditampilkan.

E. RUANG KONTROL PIMPINAN
1. Buka Manajemen User.
2. Edit akun pimpinan.
3. Pilih bidang yang diawasi: akademik, tahfiz, pengasuhan, kesehatan, konseling, sarpras, observer, SDM, keuangan, dan lain-lain.
4. Pilih wilayah: Putra, Putri, atau Semua.
5. Pilih kewenangan: Melihat, Tindak Lanjut, atau Mengelola.
6. Simpan.
7. Dashboard Pimpinan hanya memuat bidang yang menjadi tanggung jawab akun tersebut.
8. Akun pimpinan lama yang belum memiliki ruang kontrol akan tetap melihat semua bidang untuk kompatibilitas.

F. WHITE-LABEL UNTUK PESANTREN LAIN
1. Buka menu Sistem -> Setup Aplikasi.
2. Isi nama aplikasi, nama lembaga, tagline, tahun ajaran, domain, warna, logo, favicon, dan istilah internal.
3. Isi konfigurasi Firebase proyek pesantren baru.
4. Pilih modul yang digunakan.
5. Import CSV santri dan SDM menggunakan template pada folder templates.
6. Unduh/gunakan hasil konfigurasi untuk mengganti:
   config/tenant-config.js
   config/master-data.js
   config/firebase-worker-config.js
7. Ganti file logo/favikon pada assets/branding atau arahkan path logo dari konfigurasi.
8. Satu deployment sebaiknya digunakan untuk satu pesantren dan satu Firebase agar data tidak tercampur.

G. OPTIMASI BANDWIDTH
1. Command Center memakai lazy load; bidang belum dibuka tidak mengunduh data.
2. Portal Wali memakai indeks per santri dan batas record.
3. Chat hanya memuat inbox ringkas dan maksimal pesan terbaru.
4. Laporan memakai filter periode, limit, dan cache.
5. Foto observasi, pelanggaran, serta tindak lanjut sarpras dipisahkan dari record utama dan baru dibaca saat tombol foto dibuka.
6. Bila data observasi lama masih menyimpan foto inline, buka Optimasi Bandwidth dan jalankan hanya pilihan:
   Pisahkan Foto Observasi Lama.
7. Jangan menjalankan ulang Indeks Wali atau Indeks Chat bila sebelumnya sudah selesai.
8. Gabungkan database-indexes-bandwidth-snippet.json ke Rules aktif tanpa menghapus aturan keamanan yang lain.
9. Pantau Usage selama minimal 7–14 hari. Target internal ideal: 4–7 GB per bulan.
10. Tidak ada kode yang dapat menjamin angka mutlak karena penggunaan bergantung pada jumlah pengguna dan frekuensi membuka halaman.

H. UJI SETELAH PEMASANGAN
1. Login akun pengurus multi-peran; periksa pengelompokan sidebar.
2. Kirim chat pengurus ke wali dan balas dari wali.
3. Tutup dan buka kembali chat; pastikan riwayat tetap ada.
4. Kirim broadcast; pastikan penerima mendapat pesan pribadi dan balasan tidak tersebar.
5. Buka Dashboard Pimpinan dengan dua akun yang memiliki bidang berbeda.
6. Pastikan masing-masing hanya melihat dan mengunduh bidangnya.
7. Uji satu absensi, satu setoran, satu UKS, dan satu perizinan.
8. Periksa Firebase Usage setelah pengujian.

I. CATATAN KEAMANAN
Paket ini memperbaiki arsitektur, chat, bandwidth, dan konfigurasi white-label. Paket ini belum menggantikan Security Rules publik menjadi aturan per-peran. Jika Rules aktif masih .read=true dan .write=true, database masih terbuka. Security hardening harus dilakukan sebagai tahap berikutnya setelah seluruh halaman dipastikan menggunakan Firebase Authentication secara konsisten.
